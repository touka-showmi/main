# GitHub Pages プログラムランチャー（PWA対応）

アップロードされたランチャーをベースに、表示設定をJSONへ分離し、軽量なPWAオフラインキャッシュに対応させた構成です。

## ファイル構成

- `index.html` — ランチャー本体。検索、フォルダー別セクション表示、最近使った項目、PWA登録を担当します。
- `program-index.json` — 任意の設定ファイルです。ファイルが存在すれば、登録したHTMLだけタイトル・色・アイコン・説明・分類・順序などを上書きします。なくても一覧は自動生成されます。
- `manifest.webmanifest` — ホーム画面追加・アプリ表示用の設定です。
- `service-worker.js` — ランチャーの必要ファイルを事前保存し、開いたHTMLを自動キャッシュします。
- `offline.html` — 未保存のページへオフラインでアクセスしたときの案内です。
- `icons/` — PWAアイコンです。

## カードをカスタマイズする

HTMLファイルはGitHubリポジトリから自動検出します。`program-index.json` は必須ではありません。設定したい項目だけを `programs` 配列に記述してください。`file` が一致した項目に限り、指定したプロパティだけが自動検出値を上書きします。JSONにないHTMLも一覧に残ります。見出し（セクション）はファイルの最上位フォルダーでまとめ、`settings.sectionOrder` で並び順を決めます。`order` は同じセクション内のカード順です。

```json
{
  "version": 1,
  "settings": {
    "title": "マイ・プログラム",
    "subtitle": "自分用のHTMLツール一覧",
    "showPath": true,
    "sectionOrder": ["recent", "tools", "Archive"]
  },
  "programs": [
    {
      "file": "tools/calendar.html",
      "title": "カレンダー",
      "description": "予定を確認します。",
      "color": "#7c5cff",
      "textColor": "#ffffff",
      "icon": "📅",
      "category": "日常ツール",
      "order": 10
    },
    {
      "file": "games/puzzle.html",
      "title": "パズル",
      "description": "短時間で遊べるパズルです。",
      "color": "#1fa6a0",
      "textColor": "#ffffff",
      "icon": "🧩",
      "category": "ゲーム",
      "order": 20,
      "thumbnail": "images/puzzle-cover.jpg"
    }
  ]
}
```

- `file` は `index.html` と同じリポジトリ内からの相対パスです。`..` や絶対URLは使わないでください。空白や日本語を含むファイル名も、GitHubのファイル一覧に表示されるとおりのパスを記述します。
- `title` はカードの題名、`color` はアクセント色、`textColor` は題名の色、`icon` は絵文字などのアイコンです。
- `thumbnail` は任意項目です。指定すると、その相対パスの画像をサムネイル枠に表示します。省略すれば `icon` を表示します。
- `program-index.json` がない、またはプログラム配列が空の場合も、GitHub APIからHTMLファイルを自動検出して表示します。ファイルパスのキーワードからアイコン・カテゴリ・アクセント色・説明文をまとめて推測し、題名はファイル名を整形します。`index.html` や `main.html` のような一般名は、可能なら親フォルダー名を題名に使います。用途を推測できない場合は汎用アイコン `🧩`、フォルダーに基づく分類、ファイルパス由来の安定した色を使います。推測のためにHTML本文を1ファイルずつ取得する処理は行わないため、通信量を抑えられます。
- 設定JSONは部分上書きです。例えば `file` と `icon` だけ記述すれば、タイトル・色・説明・分類などは自動生成値のまま残ります。
- `category` はカード内に表示する用途分類、`section` は表示する大見出し（セクション）です。`section` を省略した場合はHTMLファイルの最上位フォルダー名から自動判定します。例えば `tools/calendar.html` は `tools`、`Archive/old.html` は `Archive` に入ります。
- `settings.sectionOrder` は大見出しの並び順です。初期設定は `["recent", "tools", "Archive"]` で、「最近使った項目」→「tools」→「Archive」の順になります。`recent` は最近使った項目を表す予約語です。存在しない見出し名は無視され、指定されていないセクションは後ろに名前順で追加されます。`recent` を省略した場合も先頭に自動追加されます。最近使った項目を途中に移動したい場合は、配列内に `recent` を明示的に含めてください。
- `programs` の各項目に `section` を指定すると、そのファイルだけ表示先の見出しを変更できます。`category` はカード内の用途ラベルであり、見出しの順序とは別です。
- `order` は同じセクション内のカードの並び順（昇順）です。
- `description` は説明文です。
- `showPath` を `false` にするとカード内のファイルパスを非表示にできます。

### 自動推測できる用途（JSON未登録時）

ファイル名・フォルダー名から、音声・音楽、ミキサー／サンプラー、音声エフェクト、録音・再生、ファイル共有・管理、圧縮・バックアップ、SNS／チャット、メール、ニュース、動画、画像、デザイン、画面キャプチャ、Git／GitHub、コード編集、JSON／整形、正規表現、API、データベース、URL／QRコード、Web／ネットワーク、地図／経路、翻訳、PDF／OCR、文章／メモ、フォント、計算／単位変換、カレンダー、タスク管理、タイマー、天気、ランダム生成、セキュリティ、グラフ／分析、AI、学習、金融／家計、健康／運動、自動化、ゲーム、スライド、図解、3D、シミュレーション、絵文字、クリップボード、音声文字起こし／読み上げ、テスト、ログ／監視などのカテゴリを判定します。カテゴリごとにアイコン・色・短い説明文を設定します。

- これはキーワードルールによる推定で、HTMLの実際の機能を読み取っているわけではありません。ファイル名が `index (1).html` のように汎用的な場合、名前だけでは用途を判別できません。
- ルールが複数に一致する場合は、コード内の `INFERENCE_RULES` に先に定義されたルールが優先されます。判定を増やしたり優先度を変えたりする場合は、この配列を編集してください。
- JSONで `title`、`icon`、`color`、`textColor`、`description`、`category`、`order`、`thumbnail` を指定した項目は、その指定が推測結果より優先されます。

JSONではコメントや末尾の余分なカンマは使えません。変更後、GitHubへコミットしてPagesの更新を待ってください。


## スマートフォン向けレイアウト

- スマホでは「最近使った項目」とフォルダーごとのカードを、見出しごとの横スクロールレールで表示します。指で左右にスワイプして選べます。
- タイルは縦型のコンパクトな構成にし、アイコンは通常44px、幅360px以下では42pxです。一般的なスマホ幅で2〜3枚が同時に見えるカード幅にしています。
- 横スクロールの案内を見出し付近に表示し、カードはスナップ位置に沿って止まります。PCでは従来のグリッド一覧を維持します。
- スマホのタイル内ではファイルパスを隠して、題名と説明を優先します。PCでは `showPath` 設定が有効ならパスを表示します。
- 説明文と題名は最大2行に抑え、横スクロール以外の横はみ出しを避けます。`manifest.webmanifest` と `icons/` のPNGアイコンも同梱しています。

## GitHub Pagesへの配置

1. このフォルダー内のファイルと `icons` フォルダーを、GitHub Pagesで公開しているリポジトリのルートへアップロードします。
2. **既存のHTMLプログラムはそのまま残して**、ランチャーを `index.html` として配置します。既存の `index.html` がプログラム本体の場合は、別名にするか、内容を退避してから置き換えてください。
3. `program-index.json` は任意です。存在すれば登録項目の設定と `settings.sectionOrder` を適用します。ファイルがない場合も、`github.io` のURLならGitHub APIからHTMLを自動列挙し、既定順 `recent` → `tools` → `Archive` で見出しを並べます。カスタムドメインではGitHubリポジトリをURLから特定できないため、JSONまたは保存済み一覧が必要です。
4. GitHubリポジトリの **Settings → Pages** で公開設定を確認し、HTTPSのPages URLでランチャーを一度開きます。
5. オフラインで使いたいHTMLをオンライン状態で一度開きます。次からは保存された最後のバージョンが表示されます。

## オフライン動作と制約

- PWAとService WorkerはHTTPS（GitHub Pagesの通常URLは対応）またはlocalhostで動作します。`file://` から直接開いた場合は利用できません。
- ランチャーのアプリシェルと設定JSONはインストール時に事前保存され、HTMLページはアクセス時に保存されます。オンラインで再アクセスすると、そのページのキャッシュは最新内容に更新されます。
- HTMLだけで完結するページはオフラインでも動作しやすいですが、外部API・外部スクリプト・外部フォント・サーバー通信に依存する機能は、その依存先がオフライン対応でなければ完全には動きません。
- ブラウザーやOSがストレージを消去した場合、保存済みページも失われることがあります。初回アクセスはオンラインで行ってください。
- 大量のHTMLを起動前から一括保存する設計ではありません。アクセス済みページのみキャッシュするため、通信量と処理負荷を抑えます。

## 実装上のポイント

- HTMLファイル一覧はGitHub APIで自動検出し、JSONは任意の上書き設定として扱います。JSONに設定されていないファイルも一覧に残ります。見出しは最上位フォルダー名で自動グループ化し、`settings.sectionOrder` で順番を調整します。
- 自動検出時は題名をファイル名から作り、ファイル名キーワードに応じたアイコン、または汎用アイコンを表示します。ページごとの `<title>` を読むために各HTMLを個別取得する処理は行わず、軽量性を優先しています。
- Service Workerの事前キャッシュ対象に設定JSONを必須ファイルとして含めていません。そのため、JSONが存在しないリポジトリでもPWAのインストール処理がJSONの404で失敗しません。
- Service WorkerはHTMLナビゲーションに「ネット優先＋失敗時キャッシュ」、その他の同一オリジン資産に「キャッシュ優先＋バックグラウンド更新」を使用します。
